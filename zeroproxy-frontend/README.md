# ZeroProxy – Smart Attendance System (frontend)

Angular 20 + TypeScript + HTML + CSS. Data comes from **zeroproxy-backend** (Node.js + Express + PostgreSQL).

## Run

Start the backend first (see `../zeroproxy-backend/README.md`), then:

```bash
npm install
npm start          # http://localhost:4200  (requests to /api are proxied to http://localhost:3000)
```

## First use

On a new, empty database, the login page asks you to create the first administrator. That administrator
can then create students, staff, classes and parent links. Account IDs are generated by the backend.

## What each role can do

- **Student**: see today's status in each of their classes (recorded by the classroom camera machine), their student ID, a summary per class and their attendance history.
- **Parent**: for each linked child, see today's status per class and the teachers' emails, a summary per class and the history; parents get an alert when a child is late or absent, and the student and parents get an email when the class ends (email needs setting up, see the backend README).
- **Teacher**: pick one of their classes; start and end it; change a student's status (present, late or absent) for any date, cancel or restore their classes from the calendar (today or later; cancelling removes that day's attendance for the class), see history, get alerts when a student nears the absence limit.
- **Admin**: list, create and delete accounts; create, rename and delete classes; set each class's start/end time, late limit and maximum absences; add any number of teachers and students to each class (a student can be in several classes); link parents and students (several children per parent, several parents per student); check system health and view the activity and error log.

## Notes

- To capture a face while creating a student, run `python face_live.py encoder` from the `facerecognition` folder on the same computer as this browser. Allow camera access, capture the student's face, then create the account. The encoder converts the camera image locally; the account and face template are saved together in the backend. The image itself is not stored.
- For live camera attendance, set `ZEROPROXY_DEVICE_KEY` to the backend's `DEVICE_KEY` and run `python face_live.py live` from `facerecognition`. To use several cameras, list webcam numbers or stream URLs: `python face_live.py live --cameras 0,1,rtsp://192.168.1.20/stream`. While it runs, the admin's System tab has a **View camera** button that shows the cameras (only on the computer running the scanner; nothing is recorded). Stop the live scanner while using the browser camera if the webcam is already in use. Existing students can be enrolled with `python face_live.py enroll` after mapping their dataset folders to student IDs in `student_ids.json`.
- Until the camera is configured, test scans with `npm run scan -- 2 08:05` in the backend.
- The teacher presses **Start class**, at any time on a day the class meets, and the cameras take attendance until **End class**. Outside that, faces are not scanned.
- A scan after the class's *start time + late minutes* is marked **late**. If the teacher starts after the scheduled time, the late minutes count from the real start. Each class has its own times. Pages refresh every 5 seconds, so scans appear on the teacher's sheet almost immediately.
- When the class ends, students not seen are set to **absent** automatically (past days: as soon as the teacher opens them). A class never started marks nobody absent. The teacher can change any record.
- Parent "messages" are stored by the backend and recorded in the admin log as "Message sent to …" (no real SMS is sent).
- Code layout: `src/app/api.ts` (calls to the backend, login token), `data.service.ts` (loads data and sends changes), `auth.service.ts`, `guards.ts`, `pages/` (login + 4 portals), `shared/` (tables, status badge, notifications). Each component has its own folder with a `.ts`, `.html` and `.css` file.
